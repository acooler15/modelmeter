# 日志规范

> 本项目的日志使用约定。

---

## 概述

- **日志库**:标准库 `log/slog`(Go 1.21+ 自带,零依赖,足够本项目)。
- **输出**:JSON 格式写 stdout;本地开发可通过 `LOG_FORMAT=text` 切换为
  文本格式便于阅读。
- **初始化**:`main.go` 里创建一次全局 logger,其余代码用
  `slog.Default()` 或从 `context` 传入。
- 日志内容用中文或英文均可,但**同一条日志的键名(key)必须用英文**,
  便于机器检索。

---

## 日志级别

| 级别 | 用途 | 示例 |
|------|------|------|
| Debug | 开发期细节,默认不开 | `slog.Debug("查询参数", "filter", f)` |
| Info | 正常业务事件、请求访问 | 服务启动、资源创建成功 |
| Warn | 可自动恢复的异常、降级 | 非法参数被拦截、重试后成功 |
| Error | 需要人工关注的失败 | 数据库写失败、panic 兜底 |

- 默认级别 Info(`LOG_LEVEL` 环境变量可调)。
- Debug 日志必须廉价:先判断级别再拼大对象,或直接传键值对交给 slog。

---

## 结构化字段

- 必须用键值对参数,禁止用 `fmt.Sprintf` 拼好整句再当 message:

```go
// 正确
slog.Info("计量表创建成功", "id", m.ID, "name", m.Name)

// 错误
slog.Info(fmt.Sprintf("计量表创建成功 id=%d", m.ID))
```

- HTTP 请求日志由中间件统一输出,固定字段:
  `method`、`path`、`status`、`cost_ms`、`ip`、`request_id`。

---

## 应该记录

- 服务启动/停止及关键配置(端口、数据库路径)。
- 所有写操作(创建、更新、删除)的实体 ID 与操作结果。
- 被 `Wrap` 的底层错误,带 `err` 字段和发生位置。
- 中间件兜底的 panic(含堆栈)。

---

## 禁止记录

- 密码、Token、Cookie 等凭据。
- 数据库连接串中的敏感参数。
- 用户提交的大段原文(只记 ID 和长度/摘要)。
- 同一错误在多层重复打印 —— 只在最外层记一次。
