# 接口配置 Key 打码显示与复制交互

## Goal

接口配置列表与编辑弹窗的 Key 展示交互改造:列表默认前端本地打码、每行
显示/隐藏按钮切换、明文点击复制到剪贴板;编辑弹窗回填当前 Key 并以密码框
+眼睛按钮呈现。纯前端改动,后端零改动(后端自 10-01-provider-key-plaintext
起已返回明文 `api_key`,打码只是前端展示层行为,与后端脱敏契约无关)。

## 背景

上一任务让列表明文直出后,用户实际使用中提出三点:编辑弹窗看不到当前
Key(当时是有意不回填);明文直出过于裸露,应默认部分打码;需要便捷复制。
本任务统一改造为「默认隐藏、显式切换、点击复制」的凭据展示交互。

## Requirements

1. **打码工具函数**:新建前端纯函数 `maskKey`(位置遵循前端目录结构规范),
   规则与后端原 `MaskKey` 一致:长度 ≤8 全部替换为 `*`,否则保留前 3 位
   与后 4 位、中间固定 `****`(如 `sk-****klmn`),并补中文注释说明双端口径。
2. **列表列**(`ProviderList.vue`):
   - 默认展示 `maskKey(row.api_key)` 打码值。
   - 每行加「显示/隐藏」切换按钮(link 风格,图标或文案按项目现有习惯),
     只切换该行;新增/编辑/删除触发列表刷新后全部回到打码态。
   - 明文状态下点击 Key 文本,复制完整 Key 到剪贴板:优先
     `navigator.clipboard.writeText`,不可用(非安全上下文)时降级
     `document.execCommand('copy')`;成功后 `ElMessage.success` 提示
     (文案如「API Key 已复制」),失败给中文错误提示。打码状态点击文本
     不触发复制。鼠标悬停于明文时呈现可点击样式(如 cursor/下划线)。
3. **编辑弹窗**(`ProviderList.vue`):
   - 打开编辑时回填当前明文 Key(`form.api_key = row.api_key`)。
   - 输入框保持 `type="password" show-password`:默认圆点隐藏,点击眼睛
     显示明文。输入框内不做部分打码(输入框需承载真实可提交值,圆点+眼睛
     即满足「默认隐藏、点击显示」意图),PRD 在此记录该取舍。
   - placeholder 调整为与回填语义一致(如「清空提交则沿用原 Key」);
     清空提交沿用原 Key 的后端规则零改动,新增弹窗行为零改动。
4. **范围**:仅前端;`types/provider.ts`、API 层、后端全部零改动;
   `isProviderRow` 已含 `api_key` 无需调整。

## Acceptance Criteria

- [ ] 列表默认显示打码值(`sk-****klmn` 形态),不出现完整明文。
- [ ] 点击某行「显示」仅该行变明文,「隐藏」切回;刷新列表后回到打码态。
- [ ] 明文状态点击 Key 文本,剪贴板获得完整 Key,页面出现成功提示;
      打码状态点击文本无复制行为。
- [ ] 编辑弹窗打开即有值(圆点态),点眼睛可见与列表一致的明文。
- [ ] 新增/编辑/删除流程回归正常(编辑不动 Key 提交后 Key 不变)。
- [ ] `npm run lint` 与 `npm run build`(含 vue-tsc)通过。
- [ ] 浏览器实测(临时端口+临时数据目录)走通上述交互。

## Out of Scope

- 后端任何改动(含 `MaskKey`,它仍服务于 New API 令牌)。
- 其他页面(Agent 模型清单、New API 配置)的凭据展示交互。
- 复制按钮图标、自动隐藏等未要求的增强。
