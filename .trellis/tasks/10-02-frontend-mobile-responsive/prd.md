# 前端移动端适配

## Goal

Web 界面在手机等窄屏设备下可用:布局、导航、表格、表单弹窗响应式适配。

## 背景

- 当前界面按桌面后台布局开发:MainLayout 固定 220px 左侧边栏,页面内存在固定 px 宽度的下拉/输入框、不换行的 flex 工具栏、固定宽度弹窗与多列 `el-table`。
- 全项目(`web/src`)目前没有任何 `@media` 媒体查询、响应式栅格或视口监听;手机窄屏下侧边栏挤占视口、工具栏溢出、弹窗超出屏幕宽度,基本不可用。
- `web/index.html` 已有 viewport meta,适配前提已具备。

## Requirements

1. **全局导航**:窄屏下侧边栏收起,顶栏提供汉堡按钮与抽屉式菜单;点击菜单项完成路由跳转并自动收起抽屉;桌面端导航保持现状。
2. **弹窗**:4 个业务弹窗(接口配置新增/编辑、测试详情、Agent 编辑模型、从接口添加模型)在窄屏全屏化,表单标签置顶,内容完整可见、可提交。
3. **工具栏与卡片头**:窄屏下标题+按钮、下拉+搜索+按钮等 flex 行允许换行堆叠;固定宽度的下拉/输入框在窄屏占满可用行宽;模型测试页协议选择按钮组允许换行。
4. **表格**:窄屏下允许 `el-table` 在组件内横向滚动,但页面级(滚动到 body)不得出现横向滚动条;AgentModelCard 表格的右侧固定操作列在横向滚动时保持可见。
5. **信息展示**:测试结果与测试详情的 `el-descriptions` 窄屏下降为 1 列;费率页头部的长 URL 提示允许折行,不撑爆容器。
6. **密度**:窄屏下 `el-main` 与 `el-card` 内边距适当收窄,提升有效内容宽度。

## 约束

- 单一断点 768px(≤768 视为移动端),不做多断点平板精调。
- 不新增任何 npm 依赖(含图标包,汉堡按钮用 CSS 实现)。
- 不将表格改造为卡片列表,以组件内横向滚动保证可用性,控制改动范围。
- 桌面端(>768px)回归零变更:渲染结构、视觉与现状一致。
- 遵循 `.trellis/spec/frontend/` 规范:组件样式 scoped、composable 编写模式、中文注释、界面文案中文。

## Acceptance Criteria

- [ ] 375px 视口(DevTools 移动模拟)逐页检查六个页面:无页面级横向滚动;导航、工具栏、表单、按钮均可正常操作。
- [ ] 窄屏下点击汉堡按钮展开抽屉菜单,点击菜单项跳转且抽屉自动收起;>768px 下侧边栏布局与现状一致。
- [ ] 4 个业务弹窗在窄屏全屏打开、表单标签置顶,提交与取消可用;桌面端弹窗宽度与现状一致。
- [ ] 测试结果与测试详情 descriptions 在窄屏为 1 列,桌面端列数不变。
- [ ] AgentModelCard 卡片操作按钮区窄屏可换行;其表格横向滚动时操作列保持固定可见。
- [ ] `cd web && npm run lint` 与 `cd web && npm run build`(vue-tsc + vite)全部通过。

## 非目标

- 平板多断点精细优化、暗色模式、PWA、触摸手势增强、表格列的移动端裁剪(仅保证横向滚动可用)。
